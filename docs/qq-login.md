# QQ 登录接入条件（2026-10-01 核实）

当前仅完成条件调研，尚未接入 QQ 登录，也未添加不可用按钮。

## 官方申请条件

1. 使用 QQ 账号注册 QQ 互联开发者，提交个人或企业资料并通过审核。
2. 创建网站应用，提交名称、图标、网站域名和回调地址，取得 AppID 与 AppKey，并通过应用上线审核。
3. 官方《应用审核规范》要求网站及回调地址在工信部完成备案，平台备案信息与工信部一致。不能因为部署在 Cloudflare 就推断可以免备案。
4. 官方《创建应用》同时提示国际域名的网站可邮件申请审核；InnerOS 的 `inneros.asia` 应先向 QQ 互联确认这条申请路径及备案要求，不保证例外获批。无需为调研变更 DNS、购买服务器或申请付费服务。
5. QQ 登录按钮遵循官方视觉规范，授权成功后提供与普通账户同等的功能，不能强制 QQ 用户填写 QQ 邮箱或另设应用密码。

## InnerOS 技术接入方案

- Web 与当前桌面端优先共用网站 OAuth 回调，通过 Cloudflare Function 完成授权码交换；AppKey 只放 Cloudflare Secret。
- 新增第三方身份表保存 Provider + OpenID/UnionID 与 InnerOS 用户关联；老账户绑定必须先验证老账户，不能按第三方昵称或推测邮箱自动合并。
- QQ 授权不等于 QQ 邮箱验证。QQ 新账户的邮箱与密码可为空，后续邮件重置只对已验证绑定的邮箱开放；现有 users.email/pass_hash 非空约束需要显式迁移后才能支持。
- 登录请求带单次 state，校验回调与会话；不把 access_token、AppKey 交给网页或写入日志。
- 桌面外链目前由默认浏览器打开，若采用浏览器授权需要补上桌面回跳与凭证交接，并分别测试；仅在网页加一个按钮不等于桌面端已经支持。
- 若以后做 Android 原生 QQ 登录，还需移动应用资料、Android 包名和签名、官方 SDK 适配；不能直接照搬 Windows 外壳。
