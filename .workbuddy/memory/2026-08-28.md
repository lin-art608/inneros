## InnerOS 项目审计与修复

### 背景
用户给两份需求文档（InnerOS_V1.0 / V1.1）并要求按文档修改 `inneros` 仓库后由 GitHub Desktop 提交推送。

### 审计结论
- 数据层：IndexedDB（entries / teams 两表），无登录/数据库，符合"账号后置"原则。
- 添加工作流：两步式（选类型→对应表单）已实现；电影=豆瓣搜索、书籍=Google Books，已删除评分/标签手填。
- 记录模型：entries[] 多次追加 + 照片上传 已实现。
- ❌ 违规点（已修复）：Sports（CS/足球）页面把第三方外链当主体——
  - 比赛卡片是 `<a href="hltv.org/...">`、焦点卡 `onclick=window.open`、顶部 scale-switcher 外链按钮、联赛卡外链。
  - 违反 V1.1 §11/§19「资源整合不是导航 / Sports 不以第三方跳转链接为主体」。

1. 音乐类型无 search→import 数据源（V1.1 明确要求"音乐必须搜索后导入"）—— 当前缺口最大。
2. Sports 仍是静态赛程数据，未真正 fetch/持续更新（Adapter 架构已预留，last_synced 缓存逻辑在但无真实请求）。
3. 事件详情未在顶部突出"地点+时间"（V1.1 §7.2）。
4. 资源页的"AI工具/常用资源"仍是外链列表——属资源导航概念，与 Sports 数据聚合不同，建议明确区分或弱化。
