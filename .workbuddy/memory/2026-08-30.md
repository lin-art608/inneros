### 踩坑
1. **E2E 断言写了 `last_seq == base + 2` 连错两次**：`operations.seq` 是**全局 AUTOINCREMENT**，不是每账号从 1 开始；新账号首条 op 的 seq 取决于表里已有行数。断言必须按实际 seq 相对写，不能按条数推算。
2. 本地 wrangler 的 D1 是持久化的（`.wrangler/`），历史测试账号/操作会累积，基线不要假设为 0（不过 last_seq 本身按 user_id 过滤，新账号仍是 0）。
3. wrangler 未预装：`npm i --no-save wrangler`（node_modules 已 gitignore，`--no-save` 保证 package.json 不动）。启动耗时约 50s。
4. 本机 Node 的 `Array.prototype.concat` 被裁（既有约定），新代码只用 spread。

## 关键教训（本批踩坑）

1. **Service 必须抛 `ServiceError`**。media/memory service 原用本地 businessError 造裸 Error + `.code`，导致 v1 路由 `e instanceof ServiceError` 判否 → **所有业务/第三方错误全变 500 INTERNAL**。E2E 第 8 项（非法 id）才暴露出来——单测覆盖不到路由判定。以后写 Service 直接用 `new ServiceError(code, msg, {status, retryable})`。
2. **E2E 要覆盖异常分支**，不能只测 happy path；本批正是异常用例抓到上面的错误模型缺陷。
3. D1 无交互式事务，要原子就 `db.batch([stmt...])`；先读后写的逻辑只能靠幂等 + 重试语义。
4. `operations.seq` 全局自增（不是每账号从 1 开始）——写断言别用条数推算 seq（已写进 AGENTS.md 踩坑清单）。

## 剩余风险
- 前端电影链路的 v1 切换未做真实浏览器手工验证（沙箱无浏览器），仅经 wrangler 接口级 E2E + 回退路径设计保证。
- 书籍仍是旧链路（ARCH-010 迁移），书籍详情走的仍是 `/api/douban?type=detail&kind=book`。
- `POST /api/v1/memories` 直接写库**不产生 operation**，所以云端直接创建的记录不会经 op log 推给其他设备；多设备同步仍依赖客户端本地 op 上报（既有设计，未改）。
